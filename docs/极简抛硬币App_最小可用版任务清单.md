## 2. 实现过程中与原计划的偏差

记录在这里，是因为这些改动都有具体原因，以后回看才知道为什么这么做。

| 原计划 | 实际做法 | 原因 |
| --- | --- | --- |
| 硬币悬空正对镜头 | 躺在看不见的水平面上，镜头斜上方看 | 对照参考视频，"落在平面上"才有真实感 |
| 落地后弹三下 | 边缘先着地 → 打转摇摆 → 躺平，共 11 次磕碰 | 实测参考录音，真硬币几乎不弹，主要是边缘磕碰 |
| 镜头固定 | 落定后绕到上方并推近成特写 | 参考视频的分镜，也是"揭晓结果"的仪式感来源 |
| 等待时硬币悬浮呼吸 | 硬币静卧，改由镜头缓慢游移 | 硬币躺在平面上还浮起来，自相矛盾 |
| 只有落地一声 | 抛起 + 落地 + 一串磕碰 | 参考录音里抛起也有声音，且余韵很长 |
| 单一贴图 | 贴图 + 法线贴图 + 环境贴图 | 没有法线图，浮雕像印花；没有环境反射，金属发灰 |
| 弹性 0.2 | 0.055 | 真硬币落在硬平面上几乎不弹 |

## 3. T23 真机调手感

**依赖**：T01 的真机部分（手机连上、开发者模式、Team 签名）

### 要做什么

装到真 iPhone 上反复抛，只调数值，不改流程。可调的都在这几处：

| 文件 | 可调的东西 |
| --- | --- |
| `Model/StyleProfile.swift` | 抛起高度上下限、落地小跳的高度 |
| `Logic/FlipPlanner.swift` 开头 | 力度映射的速度区间、翻转圈数、下落减速、落地倾角、打转圈数、磕碰节奏 |
| `Scene/SwipeDetector.swift` 开头 | 上划的距离门槛、速度门槛、允许的倾斜 |
| `Scene/CoinSceneView.swift` 开头 | 镜头角度距离、推近速度、亮度、跟手的黏滞感 |
| `Feedback/HapticPlayer.swift` 开头 | 震感：`gain` 总强度、`floor` 最轻一下的下限、落地闷响 |
| `scripts/make_assets.py` 开头 | 贴图图案、`MOTIF_RING_ERASE` 凸起上擦净同心纹的程度、环境明暗、音色 |

### 验收标准

- [ ] 轻轻一划：硬币低低抛起，翻转较少
- [ ] 用力一划：明显更高更快，但不飞出屏幕
- [ ] 从上划到停稳，最长一次在你能接受的等待时间内
- [ ] 上划的门槛合适：手抖不会误触发，正常一划一定能触发
- [ ] 震动的轻重和画面对得上
- [ ] 停稳前那串"嗒嗒嗒"摸得到，且一路变轻（这是换精细震动引擎的目的）
- [ ] 调完后 `./scripts/test.sh` 全部通过（特别是结果一致性那组）
- [ ] 连续玩 5 分钟没有觉得别扭的地方

### 已经决定的

- **力度把"划的距离"也算进去了**：速度占七成、距离占三成，
  在 `FlipPlanner.forceFactor`。要改比重就调那里的 `speedWeight`。

## 5. T25 边缘立币（第三种答案）

**依赖**：T24 必须先完成。

**为什么要等**：这是一个新功能，而且会动到"结果"这条贯穿全身的主线。
主线还没验收完就动它，出了问题会分不清是新功能带来的，还是原来就有的。
先给"这个版本是对的"打一个桩，再开工。

### 要做的是什么

极低概率下，硬币落地弹几下之后**竖立在边缘上**，不给日也不给月。
震动与平常完全不同，屏幕中央浮现一道极细的高光。
它不只是彩蛋，是打破二选一的"第三种答案"。

### 开工前必须先定的三件事

| 要决定的 | 两条路 | 备注 |
| --- | --- | --- |
| **概率** | 1/1000 当传说 / 1/200 当彩蛋 | 一个人一辈子大概抛两三百次。1/1000 等于绝大多数人永远见不到，而且真撞上的人第一反应多半是"卡 bug 了"。倾向 1/200 |
| **立住之后呢** | 只是"这次没结果，再抛" / 就这么立着，什么都不说 | 后者才是"第三种答案"。要一并想清楚：冷启动读到上次是立币，应该还立在那儿 |
| **要不要写明概率变化** | — | 加了之后日月各是 49.95%，不再是严格五五开。实际无所谓，但本项目一直是"结果先定、动画只负责演"，这条性质该在技术文档里写明，不能悄悄改掉 |

### 难在哪、不难在哪

**几乎免费**（现有机制直接能用）：

- **立币的姿态** —— 现在的落地流程是「边缘先着地 → 歪着打转 → 收平躺下」，
  立币就是**不要最后那一步收平**。翻转角度从"若干个半圈"改成
  "若干个半圈再加四分之一圈"，硬币自然停在竖着的位置。摇摆那套递减原样能用。
- **震动** —— 精细震动引擎正好擅长这个。换一张震动表即可：
  一串越来越快越来越轻的脆响（在边上来回晃），最后一记沉的定住。
- **概率** —— 决定结果的地方只有一行。

**要花力气**：

- **镜头** —— 现在的特写从正上方 78 度俯看，立着的硬币从上面看就是一条线。
  立币要配一套自己的分镜：压到很低的角度平视过去。
- **阴影** —— 躺着投圆影，立着投细长条。现在的阴影是等比缩放的圆片，
  要支持两个方向分别缩放。
- **那道高光** —— 全新的东西，不是任何现有参数的调整，要反复试几轮。
- **减少动态效果模式** —— 也得想好立币在简化动画下怎么呈现。

### ★ 真正会咬人的一处 ★

「结果」这个类型从头到尾只有两个值：日、月。它串在存档、状态机、
半圈数奇偶修正、静置姿态，以及一组专门反向验证
"演完之后朝上的面必须等于当初决定的结果"的测试里。

加第三种结果，等于把这条贯穿全身的线换掉。改动本身不难，**难在容易漏**。
漏一处的后果不是崩溃，是"偶尔结果不对"——在抛硬币 App 里这是致命的，还极难复现。

**所以第一个子任务必须是：把结果类型和那组一致性测试改成三值，让测试先红。**
红了之后再去改代码，漏哪儿它会立刻告诉你。这组测试已经抓到过两次实现上的错。

### 拆解（开工时再细化）

1. 结果类型改为三值，一致性测试同步改三值 —— **先让测试红**
2. 存档与冷启动支持第三种结果
3. 时间表支持"停在竖立"：四分之一圈收尾 + 专属的弹跳与摇摆
4. 立币专属镜头
5. 阴影支持非等比缩放
6. 立币专属震动与声音
7. 中央那道极细的高光
8. 概率接进随机器，并补一个"大量抛掷后三种结果占比符合设定"的测试

### 验收标准

- [ ] 把概率临时调成 1/2，连抛十次，立币的姿态、镜头、阴影、震动、高光都对
- [ ] 概率调回正式值后，一致性测试全部通过（含三值反向验证）
- [ ] 立币之后切后台再回来，不会变成日或月
- [ ] 立币之后冷启动，硬币仍然立着
- [ ] 开启"减少动态效果"后，立币仍能正常呈现

| 项目 | 为什么必须 |

## 7. 日常命令

```bash
cd ~/CoinFlip
./scripts/test.sh    # 跑测试
./scripts/run.sh     # 在模拟器里打开
./scripts/doctor.sh  # 环境出问题时诊断
open CoinFlip.xcodeproj   # 用 Xcode 打开（真机运行走这里）
```

**真机运行**：Xcode 打开项目 → 左侧点最上方 CoinFlip → TARGETS → CoinFlip →
Signing & Capabilities → Team 选你的 Apple ID → 顶部设备选你的 iPhone → `⌘R`
