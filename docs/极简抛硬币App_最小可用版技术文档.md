# 极简抛硬币 App 最小可用版技术文档

- 对应需求：《极简抛硬币 App V1 需求文档》的最小可用子集
- 采用方案：方案 A（Swift + SwiftUI + RealityKit 精简版）
- 平台：仅 iPhone，仅竖屏，离线运行
- 文档用途：交给开发者或 AI 编程助手作为实现依据，并作为真机验收清单

---

## 1. 本版范围

### 1.1 本版要做

| 功能 | 说明 |
| --- | --- |
| 全屏硬币 | 打开即全屏 3D 场景，中央一枚银色硬币；无按钮、无文字、隐藏状态栏 |
| 上划抛掷 | 上划触发抛掷；上划越快抛得越高，有上下限 |
| 随机结果 | 上划瞬间独立随机决定日面或月面，概率各 50% |
| 结果与动画一致 | 动画按预先决定的结果倒推，最终朝上的面必须等于决定的结果 |
| 落地表现 | 腾空翻转 → 落地 → 小弹一下 → 停稳 |
| 落地声震 | 首次落地时同时播放一声金属撞击声和一下震动 |
| 运动中忽略上划 | 从抛掷开始到完全停稳，任何上划都被忽略，不排队、不叠加 |
| 保存最后结果 | 决定结果的瞬间保存；冷启动时以该面朝上静置显示 |
| 基础后台处理 | 抛掷中切后台或被来电打断：立刻停声，硬币直接摆成结果面并静置 |
| 遵循静音 | 静音键打开时不出声，画面和震动照常 |

### 1.2 本版暂缓（留到后续版本）

| 暂缓项 | 本版替代做法 |
| --- | --- |
| 青铜、深金两种风格及长按切换 | 只做银币；代码中保留"风格档案"结构 |
| 精细浮雕与高级金属材质 | 简单圆柱模型 + 日/月贴图 + 基础金属材质 |
| 陀螺仪驱动高光 | 固定灯光角度 |
| 多次衰减弹跳与衰减震动 | 只弹一下 |
| 摩擦声、风声等多层音效 | 只有落地撞击声 |
| 悬浮呼吸动画 | 硬币静止 |
| 冷启动与后台恢复的区别对待 | 统一为"结果面朝上静置" |
| 减少动态效果模式 | 正式上架前补齐 |
| 首次光点引导 | 交给他人使用前补齐 |

## 2. 技术选型

| 用途 | 选用 | 理由 |
| --- | --- | --- |
| 编程语言 | Swift | 苹果官方语言，只做 iPhone 时最直接 |
| 界面外壳 | SwiftUI | 全屏、隐藏状态栏、识别上划手势都很简洁 |
| 3D 渲染 | RealityKit | 苹果当前主推的 3D 框架，金属材质效果好；后续升级完整版无需更换 |
| 硬币模型 | 程序生成的扁圆柱，或简单 USDZ 模型 | 省掉精细建模成本，先验证手感 |
| 震动 | UIImpactFeedbackGenerator | 系统自带，最简单；完整版再换 Core Haptics 做精细编排 |
| 声音 | AVAudioPlayer，音频会话类别 `.ambient` | 只播一个音效，简单可靠；`.ambient` 自动服从静音键且不打断用户的音乐 |
| 本机保存 | UserDefaults | 只存一个值，系统自带即可 |
| 开发工具 | Xcode（需要 Mac） | iOS 开发必需 |

**为什么不选其他方案**

- 纯 SwiftUI 伪 3D：最快，但硬币没有厚度和金属感，升级时画面部分要重写。
- SceneKit：资料多，但苹果已于 2025 年宣布其进入只维护状态，后续大概率需迁移。
- Unity：为一枚硬币引入整个游戏引擎，体积大、启动慢，iOS 震动与静音细节更难做到位。

## 3. 整体架构

### 3.1 模块划分

| 模块 | 职责 | 打比方 |
| --- | --- | --- |
| 手势识别 | 识别上划并测量速度 | 观众的手 |
| 状态管理 | 记录硬币当前状态，决定是否接受上划 | 门卫 |
| 随机器 | 五五开决定日/月 | 信封里的答案 |
| 演出规划师 | 根据速度和结果生成本次抛掷的时间表 | 写分镜的导演 |
| 3D 舞台 | 每一帧按时间表摆放硬币位置和角度 | 摄像机 |
| 声震播放 | 到落地时刻播放声音和震动 | 音响师和震动座椅 |
| 本机存储 | 保存与读取最后一次结果 | 抽屉 |
| 生命周期 | 处理切后台、来电打断、冷启动 | 剧场管理员 |

### 3.2 数据流转

```
手指上划
   │ 测速度
   ▼
【状态管理】当前是"抛掷中"？ ── 是 → 忽略
   │ 否
   ▼
【随机器】决定 日/月
   │
   ├──→ 【本机存储】立刻保存结果
   │
   ▼
【演出规划师】速度 → 高度（限制在上下限之间）
              当前朝上面 + 结果 → 翻转半圈数（奇偶决定朝向）
              生成时间表：落地时刻、弹跳高度、停稳时刻
   │
   ▼
【状态管理】切换为"抛掷中"
   │
   ├──→ 【3D 舞台】每一帧：根据经过的时间，计算并设置硬币高度与角度
   └──→ 【声震播放】到达落地时刻：撞击声 + 一下震动
   │
   ▼
到达停稳时刻 → 角度归零到结果面 → 状态切换为"静置中"
```

### 3.3 旁路流程

```
冷启动
   → 从本机存储读取最后结果
   → 有结果：该面朝上静置；无结果：日面朝上，状态为"等待中"

抛掷中切后台 / 来电打断
   → 立刻停止声音
   → 硬币直接摆成本次结果面，角度归零
   → 状态切换为"静置中"（结果早已保存，无需重新随机）
   → 返回前台时保持静置，不续播动画

未抛掷时切后台再返回
   → 保持原状态不变
```

## 4. 数据结构

```swift
// 硬币的两面
enum CoinFace: String, Codable {
    case sun    // 日
    case moon   // 月

    var opposite: CoinFace { self == .sun ? .moon : .sun }
}

// 硬币状态（同一时刻只处于其中一种）
enum CoinPhase {
    case waiting                 // 新安装，还没抛过；可接受上划
    case flipping(FlipPlan)      // 抛掷中；忽略一切上划
    case resting(CoinFace)       // 落定静置；可接受上划
}

// 一次抛掷的时间表（所有时间单位：秒）
struct FlipPlan {
    let result: CoinFace         // 预先决定的结果
    let startFace: CoinFace      // 抛掷前朝上的面
    let height: Double           // 抛起高度，已限制在上下限之间
    let halfTurns: Int           // 翻转半圈数（每半圈 = 180°）
    let landTime: Double         // 首次落地时刻：播放声音和震动
    let bounceHeight: Double     // 落地后弹起的高度
    let endTime: Double          // 完全停稳时刻：解锁上划
}

// 风格档案：本版只有银币一条，但所有风格相关参数必须从这里读取
struct StyleProfile {
    let id: String               // "silver"
    let textureSun: String       // 日面贴图文件名
    let textureMoon: String      // 月面贴图文件名
    let landSound: String        // 落地音效文件名
    let bounciness: Double       // 弹性：弹起高度占抛起高度的比例
    let minHeight: Double        // 抛起高度下限
    let maxHeight: Double        // 抛起高度上限
}
```

**本机保存内容（仅此一项）**

| 键名 | 类型 | 说明 |
| --- | --- | --- |
| `lastResult` | 字符串 `"sun"` / `"moon"`，可为空 | 最后一次结果；为空表示从未抛过 |

## 5. 关键逻辑

### 5.1 随机决定结果

```swift
let result: CoinFace = Bool.random() ? .sun : .moon
```

- 只使用系统随机数，不加任何"平衡""防连续"逻辑。
- 结果决定后立刻写入本机存储，再开始动画。

### 5.2 保证最终朝向正确（最重要）

硬币每翻半圈（180°），朝上的面就换一次。因此：

- 结果与抛掷前朝上的面**相同** → 半圈数必须是**偶数**
- 结果与抛掷前朝上的面**不同** → 半圈数必须是**奇数**

```swift
func makeHalfTurns(baseHalfTurns: Int, startFace: CoinFace, result: CoinFace) -> Int {
    let needOdd = (startFace != result)
    let isOdd = baseHalfTurns % 2 == 1
    return (needOdd == isOdd) ? baseHalfTurns : baseHalfTurns + 1
}
```

`baseHalfTurns` 由上划速度换算（速度越快翻得越多），之后只能经过这个函数修正，任何地方都不能再改动半圈数。

### 5.3 力度映射

```
height    = clamp(速度 × 系数, minHeight, maxHeight)
飞行时长   = 由 height 按抛物线公式换算
landTime  = 飞行时长
bounceHeight = height × bounciness
endTime   = landTime + 弹跳时长
```

具体系数在真机上调校，调校只改 `StyleProfile` 和换算系数，不改流程。

### 5.4 每一帧的摆放

- 经过时间 `t < landTime`：高度按抛物线计算；角度从 0 匀速增加到 `halfTurns × 180°`。
- `landTime ≤ t < endTime`：角度固定在最终值，高度做一次小弹跳。
- `t ≥ endTime`：高度归零，**角度归零到干净的结果面角度**（日面 0°，月面 180°），状态切换为静置。

### 5.5 声音与震动

- App 启动时预加载落地音效，避免第一次播放延迟。
- 上划开始时调用震动器的 `prepare()`，让它提前"热身"。
- 声音与震动只在时间表的 `landTime` 触发，不在任何地方单独写死秒数。
- 音频会话类别设为 `.ambient`。

### 5.6 生命周期

通过 SwiftUI 的 `scenePhase` 监听前后台变化：

- 变为后台或非活动状态，且处于"抛掷中"：停声 → 摆成结果面 → 角度归零 → 状态改为静置。
- 返回前台：不做任何事，保持当前状态。

## 7. 开发步骤

1. 建立 Xcode 工程，设置仅 iPhone、仅竖屏、隐藏状态栏。
2. 写好 Model 与 Logic：数据结构、随机器、演出规划师、本机存储。
3. 写自动测试：模拟抛 1000 次，检查每次最终朝上的面等于决定的结果；检查结果分布接近五五开。
4. 搭 RealityKit 场景：一枚扁圆柱硬币、日/月贴图、一盏固定灯光、一个固定摄像机。
5. 接上上划手势，让硬币按时间表动起来。
6. 加入落地声和震动。
7. 加入状态管理：抛掷中忽略上划。
8. 加入冷启动恢复与后台处理。
9. 装到真机，调校力度系数、高度上下限、弹性，直到手感满意。

## 8. 真机验收清单

### 8.1 结果正确性

- [ ] 连续抛 50 次，每次落定显示的面都与本次决定的结果一致（可在开发版中临时打印结果核对）
- [ ] 自动测试通过：1000 次模拟全部一致，日/月比例接近 50%
- [ ] 轻划与猛划都能得到两种结果，力度不影响概率

### 8.2 交互

- [ ] 上划能触发抛掷，下划、左右滑、点击不触发
- [ ] 轻划抛得低，猛划抛得高，且都在合理范围内
- [ ] 抛掷中连续上划，没有任何反应，停稳后也不会补抛
- [ ] 停稳后再次上划可正常抛掷
- [ ] 界面上没有任何按钮、文字和状态栏

### 8.3 声音与震动

- [ ] 落地瞬间声音、震动与画面同时发生，无明显先后
- [ ] App 启动后的第一次抛掷，声音和震动也不迟到
- [ ] 打开静音键：不出声，画面与震动正常
- [ ] 一边播放音乐一边抛硬币：音乐不被中断

### 8.4 保存与恢复

- [ ] 新安装首次打开：日面朝上静置，可直接上划
- [ ] 抛出月面后彻底关闭 App 再打开：月面朝上静置
- [ ] 抛掷中切到后台再返回：硬币已落定为结果面，不续播动画
- [ ] 抛掷中接到来电，挂断返回：同上
- [ ] 抛掷中切后台后从后台划掉 App，再打开：显示的是本次结果
- [ ] 未抛掷时切后台再返回：状态不变

### 8.5 基本性能

- [ ] 动画流畅，无明显卡顿
- [ ] 连续抛 100 次后，结果仍正确，硬币姿态正常（验证角度归零）

## 9. 自己改代码时特别容易踩的坑

| # | 坑 | 后果 | 怎么避免 |
| --- | --- | --- | --- |
| 1 | 调动画时改了翻转半圈数 | 显示面与结果相反 | 半圈数只能经过 `makeHalfTurns` 修正；改动画后跑自动测试 |
| 2 | 角度每次在上次基础上累加 | 抛多次后显示面判断出错、动画起始姿态异常 | 每次停稳后把角度归零到 0° 或 180° |
| 3 | 在动画代码里单独写死"0.9 秒后出声" | 改高度后声音早响或晚响 | 所有时间点只从 `FlipPlan` 读取 |
| 4 | 声音、震动首次播放慢半拍 | 第一次抛掷手感差 | 启动时预加载音效；上划时调用 `prepare()` |
| 5 | 在各处写死 "silver"、弹性 0.6 等数值 | 加新风格时要满地找、容易漏改 | 风格相关的一切只从 `StyleProfile` 读取 |
| 6 | 用"等 2 秒"来解锁上划 | 动画还没停稳就能再抛 | 以 `endTime` 为准切换状态 |
| 7 | 只在落地后保存结果 | 抛掷中被系统杀掉会丢结果 | 决定结果的瞬间就保存 |
| 8 | 为了"更公平"修改随机逻辑 | 破坏五五开 | 只用 `Bool.random()`，不加任何平衡逻辑 |
| 9 | 音频会话类别设错 | 静音键失效，或打断用户音乐 | 保持 `.ambient`；改声音代码后开静音键测试 |
| 10 | 替换贴图或模型时搞反正反面 | 结果全部相反 | 约定日面在 0°、月面在 180°；换资源后跑自动测试并真机核对 |
| 11 | 只在模拟器测试 | 震动、声音延迟问题发现不了 | 所有手感相关改动都在真机验证 |

## 10. 后续升级路径

最小可用版完成后，按以下顺序升级到完整 V1。每一步都是在现有结构上"添加"，不需要重写已有的随机、时间表和状态逻辑。

1. **上架必需**：首次光点引导、减少动态效果简化动画、冷启动悬浮与后台静置的区分
2. **质感**：精细浮雕模型、高级金属材质、陀螺仪高光、悬浮呼吸、多层音效、衰减弹跳；震动升级为 Core Haptics
3. **彩蛋**：青铜、深金两种风格（向 `StyleProfile` 添加条目）+ 长按 2 秒风格选择器 + 保存所选风格
