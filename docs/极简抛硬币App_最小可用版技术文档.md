## 1. 本版范围

### 1.1 本版做了什么

| 功能 | 说明 |
| --- | --- |
| 全屏硬币 | 打开即全屏 3D 场景，硬币**躺在一个看不见的水平面上**；无按钮、隐藏状态栏 |
| App 名称 | 桌面显示 **Coin**（`CFBundleDisplayName`），同时 `CFBundleName` 填 **抛硬币**。系统除显示名外也会索引后者，所以搜中文也能找到，桌面上却只出现短名。工程与代码里仍叫 CoinFlip。完整的「coin · 抛硬币」留给 App Store 的名称字段（在 App Store Connect 填，不在 App 包里） |
| 底部状态行 | 屏幕底部常驻一行 `Coin: Ready / Tossing / Sol / Luna`，正式版也有。**这是整个 App 唯一的文字**。2026-10-09 的需求变更，原来写的是「无文字」 |
| 上划抛掷 | 上划触发抛掷；划得越快抛得越高，有上下限 |
| 随机结果 | 上划瞬间独立随机决定日面或月面，概率各 50% |
| 结果与动画一致 | 动画按预先决定的结果倒推，最终朝上的面必须等于决定的结果 |
| 抛掷动画 | 上抛匀速翻滚 → 下落减速 → 边缘先着地 → 在平面上打转摇摆 → 躺平 |
| 镜头调度 | 等待时低角度缓慢游移；落定后绕到上方并推近成特写；再次上划时快速退回 |
| 声音 | 脱手一声长余韵的"叮"；落地及之后一连串越来越密的磕碰 |
| 震动 | 与每一次磕碰同步，太轻的跳过 |
| 运动中忽略上划 | 从抛掷开始到完全停稳，任何上划都被忽略，不排队、不叠加 |
| 保存最后结果 | 决定结果的瞬间保存；冷启动时以该面朝上显示 |
| 中断处理 | 抛掷中切后台或被来电打断：立刻停声、取消未响的磕碰，直接落定为本次结果 |
| 遵循静音 | 静音键打开时不出声，画面和震动照常 |
| 金属质感 | 法线贴图 + 环境反射，浮雕的高光随硬币转动流动 |

## 2. 技术选型

| 用途 | 选用 | 理由 |
| --- | --- | --- |
| 编程语言 | Swift | 苹果官方语言 |
| 界面外壳 | SwiftUI | 全屏、隐藏状态栏都很简洁 |
| 3D 渲染 | RealityKit | 苹果当前主推；支持法线贴图与环境光 |
| 手势 | 自定义 UIView 直接处理触摸 | **SwiftUI 手势会被 RealityView 挡掉**，详见第 9 节 |

| 声音 | AVAudioPlayer，音频类别 `.ambient` | `.ambient` 自动服从静音键且不打断用户音乐 |
| 本机保存 | UserDefaults | 只存一个值 |
| 素材生成 | Python + PIL + numpy（`scripts/make_assets.py`） | 贴图、法线图、环境图、音效全部由代码生成，可复现、可微调 |
| 工程文件 | 手写的 `CoinFlip.xcodeproj`，文件夹自动同步 | 新增文件直接放进文件夹即可，不用改工程 |

## 3. 整体架构

### 3.1 模块划分

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 手势接收 | `Scene/SwipeCatcher.swift` | 盖在 3D 画面之上的透明板，直接处理原始触摸 |
| 手势判定 | `Scene/SwipeDetector.swift` | 判断算不算有效上划，量出速度 |
| 随机与规划 | `Logic/FlipPlanner.swift` | 决定结果、修正半圈数、排出完整时间表 |
| 状态管理 | `Logic/CoinController.swift` | 三态门卫，决定是否接受上划 |
| 本机存储 | `Logic/CoinStore.swift` | 只存最后一次结果 |
| 动画计算 | `Scene/FlipAnimator.swift` | 算每一帧的高度、翻转角、打转角 |
| 3D 舞台 | `Scene/CoinSceneView.swift` | 搭场景、每帧摆硬币、调度镜头 |
| 环境反射 | `Scene/StudioEnvironment.swift` | 把全景图做成环境光源 |
| 声音震动 | `Feedback/FeedbackPlayer.swift` | 按磕碰清单播放 |
| 生命周期 | `App/CoinFlipApp.swift` | 组装各部分，处理前后台 |

**分层原则**：`Model` 和 `Logic` 不依赖任何画面、声音的东西，所以它们能被自动测试完整覆盖。
`Scene` 和 `Feedback` 只负责"把时间表演出来"，不做任何决定。

### 3.2 数据流转

```
手指上划
   │
   ▼
【SwipeCatcher】透明板接到原始触摸，算出位移和抬手速度
   │
   ▼
【SwipeDetector】三道门槛：往上够远？够快？不太斜？ ── 不过关 → 忽略
   │
   ▼
【CoinController】当前是"抛掷中"？ ── 是 → 忽略（不排队、不叠加）
   │ 否
   ▼
【FlipPlanner】决定结果（五五开）
   │
   ├──→ 【CoinStore】立刻保存，先于动画
   │
   ▼
【FlipPlanner】排出一张完整的时间表 FlipPlan：
        高度、半圈数（奇偶已修正）、落地时刻、
        磕碰清单（每一次的时刻与轻重）、停稳时刻
   │
   ├──→ 【CoinSceneView】每帧向 FlipAnimator 要姿态并摆上去
   └──→ 【FeedbackPlayer】按磕碰清单排队播放声音与震动
   │
   ▼
到达停稳时刻 → 姿态归零 → CoinController 切到"静置中"
   │
   ▼
【CoinSceneView】镜头缓缓绕到上方并推近成特写
```

### 3.3 旁路流程

```
冷启动
   → CoinStore 读最后结果
   → 有：该面朝上躺着（静置）
   → 无：日面朝上，状态"等待中"，镜头缓慢游移

抛掷中切后台 / 来电 / 下拉控制中心
   → FeedbackPlayer.stopAll()：停声并取消还没响的磕碰
   → CoinController.interrupt()：直接落定为本次已决定的结果
   → 不重新随机、不续播动画
   → 返回前台时保持静置

未抛掷时切后台再返回
   → 什么都不做
```

## 4. 数据结构

```swift
// 硬币的两面
enum CoinFace: String, Codable {
    case sun, moon
    var opposite: CoinFace { self == .sun ? .moon : .sun }
}

// 硬币状态（同一时刻只处于其中一种）
enum CoinPhase: Equatable {
    case waiting                 // 新安装还没抛过；可接受上划
    case flipping(FlipPlan)      // 抛掷中；忽略一切上划
    case resting(CoinFace)       // 落定静置；可接受上划
}

// 一次抛掷的完整时间表（时间单位：秒，高度单位：米）
struct FlipPlan: Equatable {
    let result: CoinFace         // 预先决定的结果
    let startFace: CoinFace      // 抛之前朝上的面
    let height: Double           // 抛起最高高度
    let halfTurns: Int           // 翻转半圈数，奇偶决定最终朝向
    let landTime: Double         // 首次落地时刻
    let bounces: [Bounce]        // 落地后的小跳
    let contacts: [Contact]      // ★ 每一次碰到平面：时刻 + 轻重
    let endTime: Double          // 彻底停稳时刻

    struct Bounce: Equatable { let height: Double; let duration: Double }
    struct Contact: Equatable { let time: Double; let strength: Double }
}

// 风格档案：一种硬币的全部参数集中在这里
struct StyleProfile {
    let id: String               // "silver"
    let textureSun: String       // 日面贴图（法线图名 = 这个名字 + "_normal"）
    let textureMoon: String
    let tossSound: String        // 抛起的声音
    let landSound: String        // 落地与磕碰的声音
    let bounciness: Double       // 落地后小跳的高度占比
    let minHeight: Double        // 抛起高度下限
    let maxHeight: Double        // 抛起高度上限
}
```

**本机保存内容（仅此一项）**

| 键名 | 类型 | 说明 |
| --- | --- | --- |
| `lastResult` | `"sun"` / `"moon"`，可为空 | 最后一次结果；为空表示从未抛过 |

## 5. 关键逻辑

### 5.1 随机决定结果

```swift
let result: CoinFace = Bool.random() ? .sun : .moon
```

只用系统随机数，**不加任何"平衡""防连续"逻辑**。结果决定后立刻写入本机存储，再开始动画。

### 5.2 保证最终朝向正确（最重要）

硬币每翻半圈（180°），朝上的面就换一次：

- 结果与抛之前朝上的面**相同** → 半圈数必须是**偶数**
- 结果与抛之前朝上的面**不同** → 半圈数必须是**奇数**

```swift
static func makeHalfTurns(baseHalfTurns: Int,
                          startFace: CoinFace,
                          result: CoinFace) -> Int {
    let needOdd = (startFace != result)
    let isOdd = baseHalfTurns % 2 == 1
    return (needOdd == isOdd) ? baseHalfTurns : baseHalfTurns + 1
}
```

只加 1 不减 1，是为了避免速度很慢时把圈数减成 0。

**以后调动画想让硬币多翻几圈时，只能改传进去的 `baseHalfTurns`，绝不能跳过这个函数直接改最终圈数。**

### 5.3 力度映射

目前只看**抬手瞬间的速度**，不看划了多远（距离只用来判断"算不算上划"）。

```
用力程度 = clamp((速度 - 300) / (3000 - 300), 0, 1)
高度     = 在 0.12 ~ 0.65 米之间按用力程度取值
半圈数   = 在 2 ~ 7 之间按用力程度取值，再经 5.2 修正奇偶
```

### 5.4 翻转的节奏

上抛和下落是两段不同的节奏，在最高点处转速接续：

- **上升段**：匀速稳稳地转，有分量
- **下落段**：按 `descentSlowdown` 减速，贴近平面时几乎只是缓缓转动

两段的"转量"归一化成 1，所以**无论减速程度怎么调，落地时转过的总度数都不变**，结果的正确性不受影响。

想让上抛更活泼就加 `maxHalfTurns`，想让下落更从容就加 `descentSlowdown`，互不干扰。

### 5.5 落地：像真硬币一样躺平

真硬币落在硬平面上几乎不弹，主要是**边缘不停磕碰**。所以：

1. **边缘先着地**：空中故意少转 `landingTilt`（26°），落地那一刻硬币还歪着
2. **一下很小的跳**：高度只有抛起高度的 5.5%
3. **在平面上打转**：绕竖直轴转 `wobbleTurns`（1.2 圈），两头慢中间快，最快不超过每秒约 2 圈
4. **歪斜慢慢收平**：那 26° 在摇摆中收到 0，越收越慢

打转只绕**竖直轴**，不改变朝上的是哪一面，所以不影响结果。

**磕碰清单**：落地 1 次 + 小跳落回 1 次 + 边缘磕碰 9 次，共 11 次，
间隔从约 90 毫秒收到约 40 毫秒，强度从 1.0 一路衰到 0.002。
声音和震动都照这张清单触发。

### 5.6 镜头

镜头是"绕着硬币看"的，由**离地角度**和**距离**决定位置，始终望向硬币：

| | 离地角度 | 距离 | 硬币占屏宽 |
| --- | --- | --- | --- |
| 等待 / 抛掷 | 28° | 3.3 | 60% |
| 落定特写 | 78° | 2.5 | 79% |

角度低时硬币显得很扁，像躺在桌面上；绕到上方才看得清图案。
推近用 1.1 秒（慢，从容），退回用 0.22 秒（快，不耽误下一次）。
用"每帧往目标靠一点"的办法，所以中途改变目标也不会跳。

等待时镜头极缓慢地左右游移（13 秒一个来回）并轻微起伏。
**硬币本身不浮动**——它躺在平面上，浮起来就自相矛盾了。

### 5.7 声音

两种声音，都由 `scripts/make_assets.py` 合成：

| | 时长 | 衰到一半 | 衰到十分之一 |
| --- | --- | --- | --- |
| 抛起 | 1.70 秒 | 34 毫秒 | 642 毫秒 |
| 落地 | 0.95 秒 | 19 毫秒 | 249 毫秒 |

音色要点（从真实录音实测得出）：

- **97% 的能量在 4kHz 以上**。低频一多就"实"，像敲木头
- **两段式衰减**：先快掉一半，再拖一条长余韵。只有快衰减就干巴巴
- **频率成簇**（如 5310 / 5410 / 5510），互相干涉产生金属特有的颤动
- **颗粒感**：跟随余韵衰减的高频噪声，少了它太"电子"

播放时准备 5 个播放器轮流用——磕碰很密，只用一个会互相打断。

### 5.8 金属质感

三件事共同作用，缺一不可：

1. **法线贴图**。彩色贴图里的明暗是画死的，硬币一转高光跟着转，像印花。
   法线图存的是"这一点的表面朝哪个方向"，手机据此实时算明暗，高光才会跟着硬币走。
   相应地，彩色贴图里烘焙的明暗要**压得很淡**，否则两套阴影打架。

2. **环境反射**（`studio_env.png`）。金属不靠自己发亮，全靠映出周围环境。
   全景图被卷成球罩在场景外，硬币转到哪，哪片灯箱就在币面上流过去。

3. **环境必须高对比**。实测参考图的亮度呈**双峰分布**（最亮档 37%、中间调仅 11%），
   所以环境要是"大片纯白灯箱 + 暗区"，模糊半径不能大（现为 9），
   否则亮暗之间填满中间调，币面就发灰。
   底色用中灰 96 而非全黑——实测参考图最暗处也有 90 左右。

材质：金属度 0.98、粗糙度 0.13、底色近白。
方向光总亮度只有 0.35——灯开大了会**把亮暗之间填平**，和模糊过度是同一个毛病。

### 5.9 生命周期

通过 SwiftUI 的 `scenePhase` 监听。变为 `.inactive` 或 `.background` 时：
停声并取消未响的磕碰 → 若正在抛掷则直接落定为本次结果 → 清掉脱手时刻。
返回前台不做任何事。

## 9. 自己改代码时特别容易踩的坑

### 9.1 逻辑类

| # | 坑 | 后果 | 怎么避免 |
| --- | --- | --- | --- |
| 1 | 调动画时绕开 `makeHalfTurns` 改圈数 | 显示面与结果相反 | 只改 `baseHalfTurns`；改完跑 `ResultConsistencyTests` |
| 2 | 姿态在上一次基础上累加 | 抛多次后越来越歪 | 每次停稳后摆成干净的躺平姿态 |
| 3 | 在动画或声音里写死秒数 | 改高度后声音对不上画面 | 所有时间点只从 `FlipPlan` 读 |
| 4 | 声音、震动首次播放慢半拍 | 第一次抛掷手感差 | 启动时预加载；上划时 `prepare()` |
| 5 | 在各处写死风格相关的数值 | 加新风格时满地找 | 只从 `StyleProfile` 读 |
| 6 | 用"等 N 秒"解锁上划 | 动画没停稳就能再抛 | 以 `endTime` 和 `CoinPhase` 为准 |
| 7 | 只在落地后保存结果 | 抛掷中被杀掉会丢结果 | 决定结果的瞬间就保存 |
| 8 | 为"更公平"修改随机逻辑 | 破坏五五开 | 只用 `Bool.random()` |
| 9 | 音频类别设成 `.playback` | 静音键失效、打断用户音乐 | 保持 `.ambient` |
| 10 | 换贴图或模型时正反面搞反 | 结果全部相反 | 守住"日面 -90°、月面 +90°"的约定，换完跑测试并真机核对 |

### 9.2 渲染与手势类（这一版踩过的）

| # | 坑 | 现象 | 原因与对策 |
| --- | --- | --- | --- |
| 11 | SwiftUI 手势挂在 RealityView 上 | 完全收不到触摸 | 3D 视图会吞掉触摸。用盖在上面的透明 UIView 直接处理原始触摸事件 |
| 12 | 自定义 UIView 不声明尺寸 | 被算成 0×0，接不到任何触摸 | 实现 `sizeThatFits` 返回外部给的尺寸 |
| 13 | 手势识别器被其他手势取消 | 只在 `.ended` 里处理就收不到 | 直接处理 `touchesBegan/Moved/Ended`，绕开整套手势抢占机制 |
| 14 | 圆柱体的两个端面贴不同的图 | 不同系统版本表现不一，可能贴混 | 用自己生成的圆形网格各贴一张，形状由几何决定 |
| 15 | 方形平面靠透明装成圆 | 某些设备不生效，露出方块边缘 | 同上，别依赖透明 |
| 16 | 挂上自己的环境光后整体变暗 | 系统默认的环境光被替换掉了 | 自己的环境图要够亮；底色别用全黑 |
| 17 | 环境模糊过度 / 方向光开太大 | 金属发灰，没有金属感 | 两者都会把亮暗之间**填平**。金属的明暗该由高对比环境决定 |
| 18 | 彩色贴图和法线图都画满明暗 | 币面出现两套打架的阴影 | 彩色图里的明暗要压得很淡 |
| 19 | 没有环境贴图时把金属度调高 | 死灰一片 | 金属度高必须配环境反射，两者是一对 |

### 9.3 环境类

| # | 坑 | 现象 | 对策 |
| --- | --- | --- | --- |
| 20 | 模拟器卡死 | App 完全不响应任何操作，像代码坏了 | 先 `xcrun simctl shutdown all` 重启模拟器再排查代码 |
| 21 | 只在模拟器测试 | 震动、静音键、来电、真实手感全测不出来 | 凡是手感相关的改动都要上真机 |

## 10. 后续升级路径

1. **上架必需**：首次光点引导、减少动态效果简化动画、冷启动悬浮与后台静置的区分
